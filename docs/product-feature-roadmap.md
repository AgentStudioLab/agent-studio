# Agent Studio 产品功能需求规划说明书

> 版本：2026-06-06  
> 目标：面向产品上线，基于当前项目能力梳理用户常用功能、差异化亮点功能，并按 P0 / P1 给出需求优先级。  
> 范围：React + Tauri 桌面端、Bun sidecar Agent 运行时、Agent 工作区、计划任务、技能/插件、远程 IM 连接、设置与用量审计。

## 1. 产品定位

Agent Studio 是一个面向知识工作者、开发者和小团队的桌面 Agent 工作台。它不是普通 AI 聊天窗口，而是把 Agent 运行、工具调用、文件处理、长期记忆、计划任务和远程入口组织在同一个本地优先的工作空间里。

核心价值：

- 让用户把“要完成的事”交给 Agent，而不是只问单轮问题。
- 让 Agent 在受控的本地工作区内读写文件、调用工具、沉淀记忆。
- 让重复任务通过计划任务和远程 IM 自动触发。
- 让用户清楚看见 Agent 做了什么、用了哪些工具、产生了哪些文件、花了多少成本。

目标上线用户：

- 高频使用 AI 处理文档、代码、数据、运营内容的个人用户。
- 希望把常用工作流配置成专属 Agent 的专业用户。
- 有远程文件处理、定时简报、自动报表等重复任务的小团队。

## 2. 当前项目功能现状

从当前代码和文档看，项目已具备较完整的 Agent Studio 雏形。

已具备的核心能力：

- 桌面端架构：Tauri 外壳 + React 前端 + Bun sidecar，本地启动 HTTP/SSE 服务。
- Agent 会话：新建任务、任务列表、任务详情、消息流、工具调用时间线、右侧过程/文件/上下文面板。
- AGUI 事件运行时：run event append-only、SSE 恢复、跨页面 attach、单线程一个 live run 约束。
- 人工审批：工具调用审批、awaiting_approval 状态、resume/cancel 流程、危险命令防护。
- Agent 工作区：Agent 列表、Agent 详情、绑定 homeDir、Instructions、最近任务、计划任务、上下文文件夹/链接、记忆文件。
- 计划任务：manual/hourly/daily/weekdays/weekly 频率、nextRunAt、后台 scheduler、计划任务运行历史。
- Skills：扫描个人和内置技能、启用/禁用、技能文件预览、运行时技能调用记录。
- Provider 设置：API key/base URL、模型列表、Claude/OpenAI provider 方向的运行时结构。
- 权限与工具设置：全局 allowed tools、线程级 allowed tools、permission mode。
- 远程连接基础：Channels 子系统、Fake/Weixin 插件注册、微信扫码连接 UI、remote task 聚合与回发协议方向。
- 用量与审计：token/cost 聚合、工具 audit log、敏感信息 redaction。
- 基础产品化：登录、计费 gate、国际化中英、主题外观、搜索/侧栏/置顶/最近会话等桌面应用骨架。

当前主要短板：

- “首次上线用户路径”还不够闭环：从配置 key、创建第一个 Agent、选择工作区、运行第一个任务到拿到文件结果，需要更强引导。
- Agent 能力组合还偏工程化：Skills、Tools、Folders、Links、Memory、Instructions 之间的关系需要更产品化。
- 远程 IM 是强亮点，但需要从技术基础走到用户可配置、可观测、可追责。
- 多模型、多 provider、成本预算、失败恢复等上线风险点需要更完整的用户侧体验。
- 缺少模板、示例 Agent、工作流推荐和成果沉淀机制，用户冷启动成本较高。

## 3. 上线目标与衡量指标

### 3.1 P0 上线目标

- 新用户 10 分钟内完成首次可用任务：配置模型、创建或选择 Agent、运行任务、查看结果文件。
- 核心 Agent 运行稳定：刷新、重启、审批、取消、失败重试都不会丢失上下文或产生重复消息。
- 用户能管理自己的 Agent：说明、记忆、文件夹、链接、技能、计划任务可配置且可解释。
- 用户能理解风险：每次文件写入、命令执行、远程自动执行、成本消耗都有清晰边界。

建议指标：

- 首次任务完成率 >= 70%。
- 任务运行中断后可恢复率 >= 95%。
- P0 功能关键路径错误率 < 1%。
- 新用户 7 日内二次启动率 >= 35%。
- 平均每个活跃用户创建 Agent 数 >= 2。

### 3.2 P1 增长目标

- 用户把 Agent Studio 从“聊天工具”升级为“日常自动化工具”。
- 每个活跃用户至少有 1 个常用计划任务或远程触发任务。
- 模板/技能/远程连接形成产品亮点，提高留存和传播。

建议指标：

- 周活用户中计划任务使用率 >= 25%。
- 周活用户中 Agent 记忆或上下文文件夹使用率 >= 40%。
- 远程连接用户的周任务触发数 >= 3。
- 模板创建后首任务成功率高于空白创建 20%。

## 4. P0 功能需求

### P0-1 首次启动与配置引导

问题：当前设置能力存在，但用户第一次打开时需要自己理解 API key、模型、权限和工作区。

需求：

- 首次启动向导：欢迎、选择 provider、填写 API key/base URL、选择默认模型、选择默认工作区。
- API key 校验：保存前执行轻量可用性检查，失败时给出明确原因。
- 默认 Agent 创建：自动生成“我的助理”Agent，绑定默认 homeDir 和基础 Instructions。
- 权限模式说明：用“每次确认”和“自动执行高风险确认”解释 ask / act-without-asking。
- 首次任务推荐：提供 3-5 个可直接运行的任务模板，例如总结文件夹、整理会议纪要、生成日报。

验收标准：

- 未配置 API key 时，任务输入区显示可跳转的配置提示。
- 配置完成后无需重启即可运行第一个任务。
- 新用户没有创建 Agent 时，系统有可用默认 Agent。

### P0-2 任务运行核心体验

问题：Agent Studio 的核心是稳定、可解释的长任务运行。

需求：

- 任务详情页展示：消息、思考/进度、工具调用、文件变更、上下文、运行状态。
- Stop / Retry / Regenerate：支持停止、失败后重试、重新生成，且文件回滚策略清晰。
- 排队输入：运行中继续输入自动排队，任务结束后按顺序发送。
- 刷新恢复：应用刷新或重启后，能恢复 running / awaiting_approval / completed 状态。
- 错误友好化：API key 缺失、模型不可用、权限拒绝、网络中断、工具失败分别给出建议动作。
- 结果定位：任务完成后突出展示新增/修改文件、最终摘要和下一步建议。

验收标准：

- 同一线程始终只有一个 live run。
- 运行中刷新页面后不会丢消息、不重复持久化消息。
- 任务失败后用户能从界面理解失败原因并选择重试或复制错误信息。

### P0-3 Agent 工作区管理

问题：Agent 是产品核心对象，需要从“会话归属”变成用户可理解的工作空间。

需求：

- Agent 创建/编辑/归档/置顶：名称、头像、homeDir、说明。
- Instructions 管理：可编辑、保存、恢复默认，并提示会影响后续任务。
- 工作目录与文件夹挂载：展示 homeDir、额外挂载文件夹、只读/可写权限。
- 链接上下文：添加 URL，Agent 可按需参考。
- 最近会话：Agent 详情页显示该 Agent 下的任务历史。
- Agent 删除保护：有运行中任务或计划任务绑定时，提示先处理依赖。

验收标准：

- 从 Agent 详情页发起任务时，任务自动绑定 Agent 并使用 Agent homeDir。
- 用户能清楚区分 Agent 的长期配置和单次任务上下文。

### P0-4 记忆与上下文沉淀

问题：Agent Studio 的复用价值来自长期记忆和上下文，不应只是聊天记录。

需求：

- Memory 文件树：展示 Agent 通过 remember 工具沉淀的记忆。
- 记忆来源追踪：每条记忆展示来源任务、创建时间、类型。
- 记忆编辑/删除：用户可以修正错误记忆。
- 上下文面板：任务运行时展示本次加载的 Skills、MCP/工具、文件夹、链接、记忆。
- 记忆冲突提示：当新记忆覆盖旧记忆时给出可审计记录。

验收标准：

- 用户能从 Agent 详情页查看并管理所有长期记忆。
- 任务上下文面板能解释“为什么这个 Agent 会这样做”。

### P0-5 Skills 与工具权限

问题：Skills 是可扩展能力入口，但上线版本必须安全、可控、可理解。

需求：

- Skills 列表：展示内置、个人、项目技能，支持搜索、启用/禁用。
- Skill 详情预览：显示名称、描述、文件内容、来源路径。
- 运行时技能记录：任务上下文展示本次调用过的 Skill。
- 默认工具白名单：提供常见工具集预设，例如安全浏览、文件读写、开发工具。
- 线程级工具覆盖：用户可为单个任务临时调整 allowed tools。
- 危险工具强审批：删除、重置、批量覆盖等操作无论白名单如何都要显式确认。

验收标准：

- 用户启用/禁用 Skill 后，新任务立即生效。
- 审计日志能记录关键工具调用、参数摘要、审批结果。

### P0-6 计划任务

问题：计划任务是从一次性使用到持续使用的关键功能。

需求：

- 创建计划任务：名称、描述、prompt、Agent、工作目录、模型、权限模式、频率、执行时间。
- 频率支持：手动、每小时、每日、工作日、每周。
- 运行历史：展示每次运行生成的会话、状态、时间、错误。
- 启用/暂停/手动运行：用户可随时控制任务。
- Keep Awake 提示：说明桌面应用关闭时计划任务不会执行。
- 计划任务安全：自动执行模式下仍遵守工作区和危险操作限制。

验收标准：

- 到点任务能通过同一 runWorker 路径创建会话并运行。
- 用户能从计划任务详情进入每次运行的 TaskView。

### P0-7 设置、账户、用量与审计

需求：

- 账户与登录状态：显示当前用户、登录/退出、订阅状态。
- 模型设置：provider、API key、base URL、默认模型、模型刷新。
- 权限设置：默认 permission mode、默认 allowed tools。
- 外观设置：语言、明暗模式、主题。
- 用量统计：按日/周/月展示 token、费用、run 数量。
- 审计日志：展示工具调用、审批、失败、远程任务回发，支持搜索和导出。

验收标准：

- 用户能知道每次任务大概消耗多少。
- 敏感信息在审计日志中默认脱敏。

### P0-8 文件预览与成果交付

需求：

- 文件树展示新增/修改/读取文件状态。
- Markdown、代码、表格、演示文稿、PDF、图片具备基础预览。
- 支持用系统默认应用打开文件。
- 支持复制路径、在 Finder/Explorer 中显示。
- 任务完成后自动汇总成果文件。

验收标准：

- Agent 生成文件后，用户不需要去文件系统里寻找结果。
- 文件不在允许工作目录内时，预览接口明确拒绝并提示原因。

## 5. P1 功能需求

### P1-1 远程 IM 文件任务

价值：这是 Agent Studio 最有辨识度的亮点之一，用户可以通过微信等 IM 把文件发给 Agent，让桌面端后台处理并回发结果。

需求：

- 远程连接管理：微信扫码绑定、启用/暂停、重连、状态检查、最近活动。
- 默认 Agent/工作区绑定：每个连接绑定一个默认 Agent 和工作区。
- 文本与文件聚合：支持先发文件后发说明、先发说明后发文件、只发文件、只发文字。
- 任务隔离：每个远程任务有独立 input/output 目录。
- 回发协议：只允许回发当前 remote task 的 output 目录文件。
- 远程任务列表：展示来源、发送方、状态、输入文件、输出文件、关联会话。
- 失败回执：Agent 失败、文件过大、权限拒绝时，向 IM 回发可读摘要。

验收标准：

- 用户通过微信发送文件和要求后，桌面端创建可追踪任务。
- Agent 完成后，微信收到简短摘要和结果文件。

### P1-2 模板与示例 Agent

价值：降低冷启动，让用户快速感知“这个工具能做什么”。

需求：

- 内置 Agent 模板：文档整理、代码助手、数据分析、内容运营、会议助理、研究助理。
- 任务模板：日报、周报、竞品分析、PDF 总结、Excel 清洗、PPT 大纲、代码 review。
- 模板创建向导：选择模板后自动生成 Agent Instructions、推荐 Skills、默认工具权限。
- 用户自定义模板：把成熟 Agent 保存为模板。

验收标准：

- 新用户可以不写复杂 prompt，直接从模板创建可运行 Agent。

### P1-3 工作流编排

价值：把 Agent 从“会话”升级为“自动化流程”。

需求：

- 多步骤工作流：触发器、Agent 步骤、文件处理、条件判断、通知回发。
- 工作流运行历史：每一步状态、输入输出、失败重试。
- 常见触发器：手动、计划任务、远程 IM、文件夹新增文件。
- 常见动作：运行 Agent、生成文件、发送 IM、打开网页、执行脚本。

验收标准：

- 用户能用可视化方式配置一个“每天读取文件夹并生成日报”的流程。

### P1-4 多 Provider 与模型策略

需求：

- Claude / OpenAI provider 在 UI 中显式可选。
- 模型能力标签：快、强、便宜、长上下文、支持工具。
- Agent 级默认模型、任务级临时模型、计划任务模型。
- 成本预算：单次任务预算、每日预算、超预算提醒。
- 自动降级：模型不可用时可提示切换，不默认静默替换。

验收标准：

- 用户能理解自己为什么选择某个模型，以及成本差异。

### P1-5 知识库与检索增强

需求：

- 本地文件夹索引：按 Agent 绑定目录建立轻量索引。
- 文档集合：用户可创建知识库并绑定给 Agent。
- 引用展示：Agent 回答中展示参考来源文件和段落。
- 增量更新：文件变化后自动或手动刷新索引。

验收标准：

- 面向文档问答类任务，Agent 能给出可追溯来源。

### P1-6 协作与分享

需求：

- 导出 Agent 配置：Instructions、Skills 配置、工具权限、模板。
- 导入 Agent 配置：从文件恢复或迁移。
- 分享任务结果：导出对话、成果文件、审计摘要。
- 团队版预留：共享模板、共享技能、共享远程连接审批策略。

验收标准：

- 用户可以把一个成熟 Agent 迁移到另一台机器。

### P1-7 高级可观测性

需求：

- Run 详情调试页：事件序列、SSE cursor、provider 原始错误、工具耗时。
- 任务质量反馈：赞/踩后可附原因，用于优化模板和默认 prompt。
- 成本趋势：按 Agent、计划任务、远程连接统计成本。
- 失败聚类：展示最常见失败原因和修复建议。

验收标准：

- 产品团队能知道用户卡在哪类任务，用户也能自助排查常见问题。

### P1-8 插件与 MCP 市场

需求：

- 插件列表：按分类展示可安装插件和 MCP server。
- 插件权限说明：安装前展示会访问哪些资源。
- 一键安装/卸载/更新。
- 插件健康检查：连接状态、鉴权状态、最近错误。
- 官方推荐组合：按场景推荐 Skills + MCP + Agent 模板。

验收标准：

- 用户可以安全地扩展 Agent 能力，而不需要手动编辑配置文件。

## 6. 产品亮点功能建议

### 6.1 Agent Memory Map

把 Agent 的记忆、指令、绑定文件夹、链接和最近任务做成一张“能力地图”。用户进入 Agent 时，可以直观看到它知道什么、能访问什么、最近做过什么。

亮点价值：

- 解决 Agent 行为黑盒问题。
- 增强用户对长期 Agent 的信任。
- 让 Agent 不再只是一个名字，而是有成长痕迹的工作伙伴。

优先级：P1。

### 6.2 Remote File Desk

把远程 IM 收到的文件任务集中成一个“远程文件处理台”：按来源、状态、输入文件、输出文件、回发结果展示。

亮点价值：

- 与普通 AI 桌面聊天工具拉开差异。
- 适合真实办公场景：手机发文件，电脑 Agent 处理，原路回发。
- 有利于形成传播案例。

优先级：P1，但微信 MVP 可先作为 P0.5 进入灰度。

### 6.3 Task Replay

用户可以回放一次 Agent 任务：每一步读了什么、写了什么、调用了什么工具、在哪里等待审批、最终产生了什么文件。

亮点价值：

- 强化可解释性和安全感。
- 适合审计、教学、复盘。
- 复用现有 event-sourced run_events 架构，技术基础匹配。

优先级：P1。

### 6.4 One-click Turn Into Agent

从一次成功任务中，一键提取 prompt、步骤、使用过的 Skills、文件上下文和记忆，生成一个可复用 Agent。

亮点价值：

- 降低用户从“临时任务”到“长期 Agent”的门槛。
- 促进用户创建更多 Agent，提高留存。

优先级：P1。

### 6.5 Outcome Inbox

所有计划任务、远程任务、长任务完成后的结果进入一个统一成果收件箱，用户按“待查看、已处理、失败”管理。

亮点价值：

- 计划任务和远程任务运行后不会散落在会话列表里。
- 更符合用户“我回来看看 Agent 做完了什么”的心智。

优先级：P1。

## 7. 推荐上线阶段

### 阶段 1：可用闭环

目标：让个人用户稳定完成本地 Agent 任务。

范围：

- P0-1 首次启动与配置引导。
- P0-2 任务运行核心体验。
- P0-3 Agent 工作区管理。
- P0-5 Skills 与工具权限。
- P0-8 文件预览与成果交付。

### 阶段 2：复用与自动化

目标：让用户愿意把重复任务交给 Agent Studio。

范围：

- P0-4 记忆与上下文沉淀。
- P0-6 计划任务。
- P0-7 用量与审计。
- P1-2 模板与示例 Agent。

### 阶段 3：差异化亮点

目标：形成与普通 AI 聊天/IDE Agent 的差异。

范围：

- P1-1 远程 IM 文件任务。
- P1-3 工作流编排。
- P1-4 多 Provider 与模型策略。
- P1-6 导入导出与分享。

### 阶段 4：增长与生态

目标：提升活跃、留存和扩展性。

范围：

- P1-5 知识库与检索增强。
- P1-7 高级可观测性。
- P1-8 插件与 MCP 市场。
- Agent Memory Map、Task Replay、Outcome Inbox 等亮点体验。

## 8. 风险与开放问题

- 远程 IM 自动执行的安全边界必须非常清楚，尤其是文件回发白名单和工作区隔离。
- 计划任务依赖桌面应用保持运行，是否需要后台常驻或云端执行需要产品决策。
- 多 provider 支持会带来模型能力差异，工具调用、审批、token 统计都需要统一抽象。
- Skills 和插件安装存在供应链风险，上线前需要安全扫描和权限提示。
- Agent 记忆如果不可编辑或不可解释，容易降低用户信任。
- 计费 gate 与本地自带 API key 模式的商业边界需要尽早明确。
